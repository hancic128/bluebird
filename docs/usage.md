# 使用

部署完（[deploy.md](deploy.md)）配好环境变量（[config.md](config.md)）后，访问 `https://你的域名/ui` 用 `NOTIFY_AUTH_USER` / `NOTIFY_AUTH_PASS` 登录即可。

---

## 典型用法：一个 hook，多个分发渠道

> 配一个 GitHub 仓库事件来源，**一次**勾选所有你想要的渠道（Bark 主力机、飞书群、Slack 频道……）。之后想关闭某个渠道、临时静音、改接收人——**面板点几下，零改脚本、零重启**。

举个具体例子：

1. 面板「通知源」→ 添加一个 GitHub 类型来源 `my-projects`，勾选 `Star` / `Pull request` / `Workflow run`
2. 面板「分发渠道」→ 已有三个实例：`My iPhone`（Bark）/ `家庭群`（飞书）/ `#dev`（Slack）
3. 回到 `my-projects` 来源的「通知渠道」勾选区：勾上这三个渠道
4. 之后任何仓库的 star / PR / CI 结果都会**并行**推到这三个渠道
5. 临时不想收到 Slack 推送：进 `my-projects` 来源详情，取消勾选 `#dev`，**保存即生效**
6. 临时关闭整个 `my-projects`：来源行的开关关掉，所有事件一律不推

> 同样的逻辑也适用于**通用来源**——你的备份脚本、爬虫、监控、cron 任务，统一 `curl -X POST https://你的域名/hooks/<来源 ID> -H "Authorization: Bearer <Token>"`，新增分发渠道都在面板点。

## 设置面板

面板右上角的 **齿轮图标** → 打开设置弹窗，分三个页签：

- **通知源**：管理 GitHub / 通用来源实例，含事件类型与分发渠道的勾选（**默认全选；全不选 = 该来源不推送**）、本人操作开关
- **分发渠道**：管理 Bark / 飞书 / 企业微信 / Slack / PushDeer / 通用 Webhook 实例，列表用各服务官方图标标识类型，展示 Key / Webhook / App 凭证与「被哪些来源引用」
- **通用**：日志保留天数、清空历史

每个页签顶部有搜索框和类型/状态过滤；列表行左侧开关用于临时启停，右侧 **编辑**（铅笔）/ **删除**（垃圾桶）按钮。

### 渠道实例常用操作

- **改接收人**：飞书渠道换群、Slack 频道等，编辑渠道改 `RECEIVE_ID` / `Webhook URL` 即可
- **测试推送**：展开某行可点「测试」直接验证该渠道配置（**不写入推送记录**），旁边的「▾」可按预置示例事件真实下发一条消息（验证配色与字段，会二次确认）
- **预览卡片**：编辑弹窗底部「预览」分组，选示例事件即可不发消息先看卡片效果
- **复制渠道**：行内复制图标以现有渠道为模板新建（名称自动 `原名-copy`；飞书沿用 App ID / App Secret 只需换接收 ID，Bark / PushDeer 的 Key、Slack 的 Webhook URL 与通用 Webhook 的签名密钥需重填）
- **渠道名**：可用中文等任意字符（≤32 字、不可重复）；它只作展示名与推送记录里的分组名，不进 URL

添加各类信息源的详细步骤见 [sources-and-channels.md](sources-and-channels.md)。

## 审计面板

顶部按来源 / 事件 / 渠道 / 时间范围筛选，列表按日期 / 来源 / 渠道分组（点击分组标题可折叠 / 展开）。每条推送以两行卡片展示：

- 首行：渠道、来源、结果、时间、标题
- 次行：正文默认折叠，内容超长才显示展开按钮

> 删除 / 失败 / 重试等状态在此追溯。常见排查步骤见 [FAQ](#faq)。

## FAQ

**为什么收不到通知？**
- 面板「审计」看该条状态是否为失败
- 确认来源的「通知渠道」勾选了对应渠道、渠道实例已启用
- GitHub 来源：App 已安装且 Webhook URL / secret 正确（创建后 App 会发 `ping`）
- 事件被过滤：仓库 owner 与 `NOTIFY_OWNER` 不一致，或操作者是本人 / 机器人；来源「事件类型」是否全不选了

**只想收部分仓库的通知？**
GitHub App 安装时选 **Selected repositories** 即可，与代码无关。

**换域名 / 换机器？**
只改 App 的 Webhook URL 和反代配置，数据卷 `/opt/bluebird` 可整体迁移（详见 [deploy.md](deploy.md#c3-数据迁移)）。

**怎么确认 webhook 真的到了服务？**
面板「审计」能查到所有入站事件。如果一条都没有：
- GitHub App 那边 `Redeliver` 看响应
- 反代 / 防火墙检查（特别是托管平台默认关入站）
- `docker logs bluebird` 看启动日志（fail-closed 警告会列在第一屏）
