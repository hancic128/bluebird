帮助页面

如何添加信息源 / 分发渠道 —— 青鸟 Bluebird 由两层组成：通知源是事件的发送方（GitHub 仓库事件 / 通用 HTTP 调用），分发渠道是通知的接收方（Bark / 飞书 / 企业微信 / Slack / PushDeer / 通用 Webhook）。两类都支持添加多个实例，互相独立启停，推送时并行分发、单实例异常不影响其他。

1进入设置

左侧菜单进入系统设置，按分组卡片排列：

分组用途
通用日志保留天数、清空全部历史
通知本人账号触发的事件是否推送（全局开关）
时区推送记录 / 最近推送时间显示的时区

通知源 / 分发渠道在左侧菜单对应页面管理：顶部搜索框与类型 / 状态过滤，列表项左侧开关用于临时启停，右侧图标依次为复制（仅渠道）、编辑与删除。

2添加通知源

GitHub 信息源

  1. 左侧菜单通知源 → 点击「添加通知源」
  2. 填写：名称（字母 / 数字 / -_.，如 github，仅作展示名，可随时改）与类型（GitHub）。Secret 无需填写：保存时由系统自动生成，在列表详情行查看 / 复制
  3. 事件类型默认全选：取消勾选的事件不推送；全不选 = 该来源不推送任何事件
  4. 通知渠道默认全选：取消勾选即不推到对应渠道；全不选 = 该来源不推送
  5. 通知本人操作：默认忽略你本人账号触发的事件，避免自扰（在「系统设置 → 通知」调整全局开关）
  6. 保存后点击列表行展开箭头，用复制按钮取该来源的 Webhook 地址（按来源 ID 生成，改名不受影响）与 Secret

再到 GitHub 仓库 Settings → Webhooks → Add webhook：

  • Payload URL：https://<你的域名>/hooks/<来源 ID>（面板来源详情里复制；旧的名字形式仍兼容，但改名后会失效）
  • Content type：application/json
  • Secret：填面板来源详情里展示的 Secret（保存时自动生成；若重新生成需同步更新此处）
  • Which events：按需选择（建议 Select individual events：star / fork / Issues / Pull requests / Workflow runs）

创建后点击 Redeliver 可立刻测试。

通用信息源

适用于任何能发 HTTP POST 的场景（脚本、CI、监控系统等）：

  1. 左侧菜单通知源 →「添加通知源」，类型选通用
  2. Token 无需填写：保存时由系统自动生成，保存后在列表详情中查看、复制或重新生成
  3. 保存后把 Token 配置到调用方

调用方式（Authorization: Bearer <Token> 必填）：

curl -X POST https://<你的域名>/hooks/<来源 ID> \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Token>" \
  -d '{"title": "构建成功", "body": "server-monitor 任务通过", "event": "build", "repo": "ops"}'
  • JSON 字段：title（标题）、body（正文）、event（事件名，配合来源级事件白名单过滤）、repo（仓库名）
  • 也支持纯文本：首行为标题，其余为正文

3添加分发渠道

渠道名称可以是任意字符（中文、空格、标点均可），最多 32 个字符，同一面板内不可重复；它只作展示名与推送记录里的分组名，不进 URL。列表右侧的复制图标可以现有渠道为模板新建：名称自动改为 名称-copy，其余配置沿用，但指向推送目标的字段不会带过去——飞书沿用 App ID / App Secret、只清空接收 ID（换群 / 换人），Slack 的 Webhook URL、Bark / PushDeer 的 Key 与通用 Webhook 的签名密钥需重新填写。

Bark（iPhone 推送）

  1. iPhone 安装 Bark App（App Store），打开后记录专属 Key
  2. 左侧菜单分发渠道 →「添加渠道」：名称如 MyIPhone，类型 Bark，填 Key（必填）与服务地址（默认 https://api.day.app，自建服务器时改）
  3. 保存。Bark 通知按信息源分组（每个来源在通知中心独立分组）

飞书（企业自建应用 · 应用机器人）

  1. 飞书开放平台 → 开发者后台 → 创建企业自建应用；在「凭证与基础信息」复制 App ID 与 App Secret
  2. 「添加应用能力」→ 启用机器人
  3. 「权限管理」开通 im:message:send_as_bot（发消息，必开；im:message 亦可）；想自动查群 ID 再开 im:chat:readonly
  4. 创建版本并发布：自建应用改权限后必须发新版本、经管理员审核通过才生效；「可用范围」要包含接收人 / 群
  5. 把机器人拉进目标群（或先与它私聊一次）——机器人不在群里发不出去
  6. 取「接收 ID」：
    • 群 → chat_id（形如 oc_xxx）：开发者后台「API 调试台」执行 GET /open-apis/im/v1/chats 查看机器人所在群
    • 个人 → open_id（形如 ou_xxx），或直接用注册邮箱（接收 ID 类型选 email）
  7. 左侧菜单分发渠道 →「添加渠道」：类型选飞书，填 App ID、App Secret，选接收 ID 类型并填接收 ID；保存后点「测试」验证
  8. 消息样式默认「卡片」：按事件类型给标题栏配色（CI 失败红 / 通过绿 / Star 黄 / PR 蓝 / issue 橙 / 评论青 / fork 紫），并在正文上方列出仓库 / 提交人 / 分支（事件类型不再单列，标题栏颜色已表达），底部带跳转按钮；有需要可改为「纯文本」（只发「一行标题一行正文」）

企业微信（群机器人）

  1. 企业微信群 → 右上角 → 添加群机器人，复制 Webhook 地址
  2. 左侧菜单分发渠道 →「添加渠道」：类型选企业微信，粘贴 Webhook 并保存

Slack（Incoming Webhook）

  1. 访问 Slack API 控制台 → Create New App → From scratch，填写应用名称与目标 Workspace
  2. 左侧 Incoming Webhooks → 打开开关 → Add New Webhook to Workspace → 选择目标 Channel → 复制生成的 Webhook URL（以 https://hooks.slack.com/services/ 开头的一长串三段路径）
  3. 左侧菜单分发渠道 →「添加渠道」：类型选 Slack，粘贴 Webhook URL 并保存
  4. 可选 消息样式：默认「卡片」（Block Kit：彩色侧栏 + header + 上下文，CI 通过/失败同事件用不同侧栏色），也可改为「纯文本」（单段 mrkdwn）

消息样式（默认卡片）按事件类型给侧栏配色（事件类型不再单列，侧栏颜色已表达），正文上方分栏列出仓库 / 提交人 / 分支等上下文，底部带跳转按钮：

事件侧栏配色卡片内容
CI 结果通过绿 / 失败红仓库、分支、提交人、运行链接
新 Star / Fork黄 / 紫仓库、提交人、仓库链接
新 PR蓝仓库、提交人、分支、PR 链接
新 issue / 评论橙 / 青仓库、提交人、issue 或评论链接
通用来源灰仓库（若推送体带 repo）

改成「纯文本」则只发「emoji + 一行标题 + 正文」，便于仅看消息流的场景。

PushDeer（iOS / Android 推送）

  1. 安装 PushDeer App 并登录，在 App 内取得专属 Key
  2. 左侧菜单分发渠道 →「添加渠道」：类型选 PushDeer，填 Key（必填）与服务地址（默认 https://api2.pushdeer.com，自建服务时改）
  3. 多个 Key 用英文逗号分隔可一次推给多台设备

通用 Webhook（自建服务 / 任意 HTTP 接收端）

  1. 左侧菜单分发渠道 →「添加渠道」：类型选通用 Webhook，填 Webhook URL（必填）
  2. 可选填签名密钥：填了则请求带 X-Bluebird-Signature-256: sha256=<HMAC-SHA256(请求体)> 头，接收端用同一密钥可校验来源
  3. 推送体为 JSON {"title","body","source"}；接收端返回 2xx 即视为成功

4验证

添加完成后回到面板主页：

  • 顶部KPI 与统计趋势图：按日查看推送量，可切换「按通知源 / 按分发渠道 / 按是否成功」，鼠标悬停查看每日明细
  • 下方推送记录：按来源 / 渠道 / 事件过滤，查看每条推送成功 / 失败状态，点击消息可展开完整内容
  • 发一条测试推送（GitHub Webhook 的 Redeliver，或通用来源的 curl），确认手机 / 群能收到

?常见问题

收不到通知？

  • 查看推送记录里该条状态是否为「失败」；检查对应渠道实例是否启用（开关）、来源的「通知渠道」是否勾选了该渠道
  • GitHub 来源：确认 App 已安装且 Webhook URL / Secret 正确
  • 检查「事件类型」是否全不选了（全不选 = 不推送）；通用来源检查 Authorization: Bearer <Token> 是否匹配

飞书渠道报错怎么查？

  • 99991672（Access denied）：应用没开通 IM 权限，或改完权限没有发布新版本——权限变更必须发版并通过审核才生效
  • 230001 / 99992402：接收 ID 或它的类型不对（群用 oc_ 开头的 chat_id）
  • 机器人不在目标群里同样发不出去：把它拉进群，或先与它私聊一次
  • 在「分发渠道」里对该渠道点「测试」，以上原因会直接显示在弹窗里，不用翻服务端日志

删除渠道后来源仍引用？

来源的「通知渠道」勾选里不会出现已删除渠道，保存一次即可清理。
